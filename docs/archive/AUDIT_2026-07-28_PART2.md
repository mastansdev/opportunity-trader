## 4. WHAT IS ACTUALLY RIGHT -- and worth knowing

**LIVE mode is safely blocked.** `trading/execution.py` raises
`NotImplementedError` if `TRADING_MODE` is set to LIVE, with an honest
message saying it is deliberate, not an oversight. Good design. Be
aware it also means going live is a whole module still to be written.

**Your own code already documents the biggest risk to MTF**, at
`engine.py:205-228`. Worth quoting because it is the sharpest thinking
in the codebase:

> "WebSocket sends periodic SNAPSHOTS, not every trade. So a dip
>  THROUGH the stop between two snapshots is never seen... This is not
>  a small bug. It means RISK_PER_TRADE_RS is not actually enforced --
>  it is the risk we take IF the feed happens to catch the breach, and
>  unbounded if it does not... a missed stop squared off at 15:15 is a
>  bad day, a missed stop carried overnight is not."

`_check_missed_stop()` reconciles against the exchange's own day
high/low and tags those exits `MISSED_STOP_RECONCILED` so they can be
counted. **Nobody has counted them yet.** That count is the number that
decides whether overnight MTF is safe at all — it should be on the
nightly review from day one.

**Position sizing is sane but the risk figure is not what it says.**

```
RISK_PER_TRADE_RS       = 2,000
MAX_NOTIONAL_PER_TRADE  = 2,00,000
```

All eleven trades today landed at Rs 1.90-2.00 lakh — **the notional
cap bound every single time**, so sizing is effectively "Rs 2L per
trade, always." The two only agree when the stop sits at ~1% of price.
Tighter stop, and real risk falls below Rs 2,000; wider, and the cap
silently overrides the risk rule. Not wrong, but "risk Rs 2,000 a
trade" is not what is happening.
