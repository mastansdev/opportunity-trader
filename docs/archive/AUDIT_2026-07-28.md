## SEVERITY 1 -- fix first

### 1a. Restart during 09:15-09:30 kills the day

Root cause above. Three fixes, pick one or all:

- Persist per-symbol tick timestamps across restart so a process gap is
  not read as a feed gap.
- Distinguish "process was down" from "feed went stale" — the first is
  our fault, the second is the exchange's.
- Whatever happens, **log it**: "SYM blocked -- ORB window unreliable"
  once per symbol, and a count on the dashboard.

### 1b. The staleness threshold is set below the feed's own rate

```
MAX_TICK_STALENESS_SECONDS = 5
```

Measured from today's heartbeats:

```
~8,900 ticks/min across 666 symbols
= 13.4 ticks per symbol per minute
= one tick every 4.5 seconds, on average
```

**The threshold is 5 seconds. The natural gap is 4.5 seconds.** Any
symbol quieter than dead average is flagged stale. That is why the
heartbeat reads:

```
stale symbols flagged: 114,528
```

There are only 668 symbols. This threshold is not detecting a fault, it
is detecting normal Dhan behaviour — Dhan sends periodic SNAPSHOTS, not
every trade. It needs to be measured per symbol against that symbol's
own typical gap, not one number for a 3,000-crore stock and a
30-crore one.

This is the same root cause as 1a. Fixing the threshold shrinks the
unreliable list even before the restart fix.

### 1c. The heartbeat label is wrong

`main.py:805` calls `get_stale_warning_count()` and prints it as
**"stale symbols flagged"**. It is a count of WARNINGS, not symbols.
Reading "114,528 symbols stale" when 668 exist has been alarming for
nothing. (Already item 12; now proven.)

## SEVERITY 3 -- the log file

### 3a. 369 MB, 3.59 million lines, no rotation

`core/logger.py` uses a plain `logging.FileHandler`. No `maxBytes`, no
`RotatingFileHandler`. It grows forever.

### 3b. 131,238 corrupted lines (3.7%)

Multiple PROCESSES append to the same file. Python's logging is
thread-safe, not process-safe. Real examples:

```
2026-02026-07-23 11:29:29,307 [DEBUG] [CANDLE] LICI closed ...
7-23 11:29:29,582 [DEBUG] [ORB] TCS range complete ...
2026-07-27 09:2026-07-27 09:15:01,144 [DEBUG] [CANDLE] RAILTEL ...
```

### 3c. Test runs write into the LIVE log

570 lines today contain pytest temp paths. Worse, tests emit lines that
are **indistinguishable from real alarms**:

```
09:26:18  [DAILY HALT] Realized P&L -8500 <= -8000 -- no new entries
09:29:00  [DAILY HALT] Realized P&L  -600 <=  -500 -- no new entries
11:36:34  [BAD_TICK] TCS rejected 105.00 -- a 47.5% jump from 200.00
```

None of those are real. TCS did not trade at 105. **I caused the 11:36
ones myself by running the test suite during this audit** — which is
exactly the point: I could not tell my own noise from a live halt
without cross-checking, and neither could you.

Tests must log to a temp file. One `conftest.py` fixture.
