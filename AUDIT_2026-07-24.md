# Full Bot Audit — Opportunity Trader

*Fable, 2026-07-24. Every Python file in the project read end-to-end and
the live decision path traced from tick to order. This is an honest
assessment: what's solid, what's fragile, what's dead, and the one thing
I think is genuinely dangerous. Nothing here is auto-fixed — it's for you
to decide what to act on.*

---

## The decision path, as it actually runs

Every tick flows through one function, `Engine.process_tick()`, in this
exact order:

1. Snapshot any pending "exit all" request.
2. Update the ORB range (only inside 09:15–09:30).
3. Update the 1-minute candle. If a candle just **closed**:
   - If a position is already open → manage its stop (ATR trail / swing
     trail / legacy fixed bracket), and maybe take a partial profit.
   - Else if the close breaks the ORB high → try a LONG entry.
   - Else if the close breaks the ORB low → try a SHORT entry.
4. Handle any manual BUY / SHORT request (dashboard buttons).
5. Circuit-proximity exit check (tick-level).
6. Trailing-stop hit check (tick-level).
7. Pending manual-exit processing.

A **structural entry** must pass, in order: not paused → price ≥ ₹200 →
before 15:15 → before 14:30 → not earnings-day → not feed-stale-in-ORB →
not frozen → not near circuit → not already blocked this direction → on
the momentum shortlist → regime agrees → a position slot is free → daily
loss/goal not hit → breakout margin cleared → no contradicting news → no
sector panic → ATR sizing succeeds → margin available. Then it opens.

That chain is coherent and every link has a clear reason. The core
machine is sound.

## What's SOLID (reviewed, trust it)

- **ORB / candle / strategy** — pure price action, well-guarded, no
  look-ahead. A signal needs a genuine candle *close*, never a wick.
- **ATR sizing** — fixed-rupee risk, with the 0.5%-of-price stop floor
  and ₹50k notional ceiling both correctly applied to entries *and* the
  ongoing trail. The SWIGGY/GODIGIT blow-up class is genuinely closed
  for structural trades.
- **Trailing stops** — both the swing and ATR paths honor "never
  loosen." Capital protection is checked every tick, not just on candle
  close. Correct precedence: stop before target on a gap.
- **Partial profit-taking** — books a real P&L record, reduces the open
  qty in place, leaves the trail untouched, fires once. Clean.
- **Restart safety** (`state_store`) — ORB ranges, positions, trails,
  capital, entry-blocks, and the momentum lock all persist; atomic
  writes; strictly same-day only, never cross-day carryover.
- **News subsystem** — runs on its own thread, AI calls are
  budget-capped, every stage isolates its own failures, and the engine
  only ever reads an in-memory index (the hot path never touches disk).
  A broken news feed cannot slow or crash trading.
- **Execution safety** — LIVE mode *raises* rather than silently
  stubbing; there is no F&O code path anywhere; paper fills are explicit.
- **Feed integrity** — frozen-price detection, circuit proximity, and
  the new ORB-window-staleness flag + tick-queue decoupling all address
  real, observed failures.

## What's FRAGILE (know these before you trust it with money)

### 1. ⚠️ Manual BUY/SHORT bypasses the entire sizing safety net — this is the dangerous one
A structural entry gets ATR sizing, the 0.5% stop floor, and the ₹50,000
notional cap. **A manual dashboard click gets none of that.** It uses the
flat 100-share placeholder and the old swing trail. So:

- Manual BUY on APAR (~₹14,000) = 100 × 14,000 = **₹14 lakh** of exposure
  in one click.
- Manual BUY on a ₹5,000 stock = ₹5 lakh. On a ₹250 stock = ₹25,000.

The size is completely divorced from risk, and the ₹50k cap that protects
every automated trade does not apply. Only the ₹200 floor and the margin
gate stand in the way. Given you actively use the dashboard BUY/SHORT
buttons, this is the biggest live-money hazard in the codebase right now.
**Recommendation:** put manual entries through the same ATR sizing (or at
least the notional cap) as structural, keeping the manual override only
for *whether* to trade, not *how big*.

### 2. Daily loss/goal guardrails reset on a mid-session restart
`_daily_realized_pnl()` reads in-memory `closed_positions`, which a
restart clears. So a restart after a −₹9,000 morning re-arms the bot to
lose another ₹10,000 before the switch trips again. Fix would be to read
the day's realized P&L from `portfolio` (which *is* persisted) or from
`trade_log.csv`.

### 3. Three different "reference points" for up/down
- Regime gate → previous-close basis (circuit snapshot).
- Momentum lock (09:30) → day-open basis.
- Sector panic → day-open basis.

None is wrong, but "is this stock up today?" is answered from two
different baselines depending on which gate is asking. Worth unifying, or
at least being aware when they seem to disagree.

### 4. Trade log is thin for analysis
`trade_log.csv` timestamps are wall-clock (`datetime.now()`), not the
tick's market time — so post-trade timing is off by the processing lag.
And there's no P&L column; every round trip has to be reconstructed by
hand (which is exactly what we kept doing this week). Adding market-time
and a per-exit realized-P&L column would make your own daily review far
easier.

### 5. No transaction costs modeled (known — POST_MARKET item 11)
Paper P&L is gross. Live results will be worse by brokerage + STT +
exchange fees + slippage — realistically ₹40–60+ per round trip plus
slippage on the fill. Any "profitable in paper" conclusion must survive
this haircut before it means anything.

### 6. No opportunity ranking (known — POST_MARKET item 8)
With the new 10-position cap, when more than 10 valid signals fire, the
bot takes **whichever candle closes first**, not the best setup. That's
arbitrary. A real ranking (liquidity / volatility / distance-of-move /
news) is still an open design question.

## What's DEAD or LEGACY (harmless, but it's clutter)

- `FIXED_TARGET_RS` / `FIXED_STOP_LOSS_RS` and `_check_fixed_bracket()` —
  only reachable by a pre-2026-07-24 position restored mid-trade across a
  restart. No new entry can create one. Kept for backward-compat; can be
  retired once no such position can exist.
- `LAYER1_FIXED_QTY` — now only used by manual entries (see Fragile #1);
  would disappear if manual sizing is fixed.
- A stray `tests/test_engine.py.bak` file (can't be deleted from this
  sandbox; harmless, pytest ignores it).

## Bottom line

The **automated** trading path is coherent, well-guarded, and every
recent fix is real. The machine that decides "should I take this
breakout, how big, where's my stop, when do I bank profit, when do I stop
for the day" is in genuinely good shape now.

The gaps are at the **edges**: manual entries are unguarded (Fragile #1,
the one I'd fix before anything else), the daily kill-switch is
restart-fragile (#2), and the honesty of paper results depends on costs
that aren't modeled yet (#5). None of these is a reason the bot *can't*
work — but #1 is a reason a single mis-click could hurt in live mode, and
#5 is why "profitable in paper" isn't yet proof of anything.

**Still true, and I won't soften it:** profitability is unproven. This
audit says the code is sound and the risks are known and bounded — not
that the strategy makes money. That verdict only comes from clean paper
sessions, one variable at a time, with costs eventually modeled in.
